================================================================================
                       CCTV & LiDAR 센서 퓨전 기반 
             공간 점유 및 위험도 스코어링 데이터 흐름 (Data Flow)
================================================================================

본 문서는 카메라(CSRNet)와 라이다(PointPillars) 센서 퓨전을 거친 BEV 공간 격자 데이터를 
가공하여, 최종 위험도 스코어링을 수행하고 데이터를 적재하는 전체 데이터 흐름을 명세합니다.

--------------------------------------------------------------------------------
1. 전체 데이터 흐름 (Data Flow)
--------------------------------------------------------------------------------

   [ Raw 데이터 입력 ] 
           │
           ├── CCTV 비디오 프레임 (카메라)
           └── LiDAR 3D 포인트 클라우드 (라이다)
           │
           ▼
   [ AI 모델 분석 (추론) ]
           │
           ├── CCTV: CSRNet 기반 군중 밀도 맵 예측
           └── LiDAR: PointPillars 기반 2D BEV 격자 점유 히트맵 예측
           │
           ▼
   [ BEV 데이터 추출 및 역투영 ]
           │
           ├── CCTV: 밀도 Peak 검출 후 호모그래피 투영 -> BEV 2D 미터 좌표로 변환
           └── LiDAR: 포인트 데이터를 160 x 120 그리드 공간 격자 맵으로 변환
           │
           ▼
   [ 센서 퓨전 및 격자 통합 (Grid-level Fusion) ]
           │
           └── CCTV BEV 가우시안 맵과 LiDAR BEV 추론 맵을 그리드별 가중치 합산 융합
               ( Fusion_Heatmap = Alpha * CCTV_Map + Beta * LiDAR_Map )
           │
           ▼
   [ 데이터 추출 (Feature Extraction) ]
           │
           ├── 프레임별 최종 융합 인원수 (Total People Count)
           ├── 보행자 중심점 2D 물리 좌표 목록 (u_m, v_m)
           └── 특정 ROI(위험 구역)별 점유 격자 밀도
           │
           ▼
   [ 위험도 스코어링 (Risk Scoring) ]
           │
           └── 사전 정의된 위험 구역(ROI) 경계 내 인원 수 및 격자 점유 밀도로 스코어 연산
           │
           ▼
   [ 데이터 적재 (Data Storage) ]
           │
           └── 시계열 CSV 파일 기록 및 RDBMS/시계열 DB(InfluxDB) 적재
           │
           ▼
   [ 시각화 및 관제 (Dashboard / Alert) ]
           └── 실시간 위험 영역 하이라이팅 및 이상 밀집 경보 발생


--------------------------------------------------------------------------------
2. 위험도 스코어링 방식
--------------------------------------------------------------------------------
특정 위험 관리 구역(ROI, Region of Interest) 별로 실시간 인원 밀집도를 평가하여 스코어링을 수행합니다.

가. 스코어 계산 공식 (Grid-level Risk Score)
    - 위험 스코어 (Risk_Score) = (w1 * ROI_People_Count) + (w2 * Mean_Occupancy_Intensity)
      * ROI_People_Count: 특정 ROI 영역 내에서 검출된 Peak(사람 중심)의 수
      * Mean_Occupancy_Intensity: ROI 영역 내 융합 히트맵 격자의 평균 확률값 (0.0 ~ 1.0)
      * w1, w2: 가중치 파라미터 (예: w1 = 15.0, w2 = 50.0)

나. 위험 등급 정의 (Risk Level)
    - [안전 (Safe)]      : 0 <= Risk_Score < 30
    - [관심 (Attention)] : 30 <= Risk_Score < 50
    - [주의 (Caution)]   : 50 <= Risk_Score < 75
    - [경계 (Warning)]   : 75 <= Risk_Score < 90
    - [심각 (Danger)]    : 90 <= Risk_Score


--------------------------------------------------------------------------------
3. 파라미터 형식 (Parameter Format)
--------------------------------------------------------------------------------
위험도 스코어링 및 융합 설정을 제어하는 파이프라인 Config 파라미터 형식 (JSON/Dict 구조)입니다.

{
  "grid_settings": {
    "x_range": [-15.0, 15.0],
    "y_range": [-15.0, 25.0],
    "grid_size": 0.25,
    "nx": 120,
    "ny": 160
  },
  "fusion_weights": {
    "cctv_alpha": 0.6,
    "lidar_beta": 0.4
  },
  "peak_detection": {
    "threshold": 0.3,
    "neighborhood_size": 5
  },
  "risk_scoring": {
    "weights": {
      "people_count_weight": 15.0,
      "intensity_weight": 50.0
    },
    "roi_zones": [
      {
        "roi_id": 1,
        "roi_name": "Cafe_Entrance_Zone",
        "boundary_poly_x": [-2.0, 2.0, 2.0, -2.0],
        "boundary_poly_y": [1.0, 1.0, 5.0, 5.0],
        "capacity_limit": 5
      },
      {
        "roi_id": 2,
        "roi_name": "Main_Counter_Zone",
        "boundary_poly_x": [-5.0, -1.0, -1.0, -5.0],
        "boundary_poly_y": [5.0, 5.0, 10.0, 10.0],
        "capacity_limit": 8
      }
    ]
  }
}


--------------------------------------------------------------------------------
4. 데이터 적재 방법 (Data Storage)
--------------------------------------------------------------------------------

가. 시계열 CSV 파일 적재 (로컬 로깅)
    - 매 프레임별 위험도 통계치 및 전체 탐지 좌표를 백업 파일로 기록합니다.
    - 파일구조: `results/sensor_fusion_summary_v3.csv`, `results/risk_history_log.csv`

나. 관계형 데이터베이스 (RDBMS - MySQL, PostgreSQL 등) 적재
    - 실시간 관제 및 대시보드 쿼리 최적화를 위해 격자 정보 및 위험 이벤트를 관계형 테이블에 적재합니다.

다. 시계열 데이터베이스 (TSDB - InfluxDB 등) 적재 (권장)
    - 초 단위 밀집도 변화 추이를 추적하고 Grafana 시각화 도구와 연동하기 위해 TSDB 데이터 적재 프로토콜을 사용합니다.


--------------------------------------------------------------------------------
5. 적재 테이블 컬럼 명세 (DB / CSV Columns)
--------------------------------------------------------------------------------

가. 테이블 1: 프레임별 센서 퓨전 요약 (sf_frame_summary)
┌──────────────────────┬─────────────┬─────────────────────────────────────────┐
│ 컬럼명 (Column)       │ 데이터 타입 │ 설명 (Description)                      │
├──────────────────────┼─────────────┼─────────────────────────────────────────┤
│ frame_id             │ INT (PK)    │ 비디오/데이터 스트림 프레임 번호        │
│ timestamp_sec        │ DOUBLE      │ 경과 시간 (초 단위)                      │
│ cctv_count           │ INT         │ 카메라 모델 단독 검출 보행자 수         │
│ lidar_added_count    │ INT         │ 사각지대 등에서 라이다가 단독 추가한 수  │
│ total_fusion_count   │ INT         │ 격자 융합 후 최종 판정된 총 인원수       │
│ max_risk_score       │ DOUBLE      │ 해당 프레임의 전체 구역 중 최고 위험도   │
│ created_at           │ TIMESTAMP   │ 데이터 적재 일시                        │
└──────────────────────┴─────────────┴─────────────────────────────────────────┘

나. 테이블 2: 보행자별 실시간 BEV 위치 이력 (sf_pedestrian_history)
┌──────────────────────┬─────────────┬─────────────────────────────────────────┐
│ 컬럼명 (Column)       │ 데이터 타입   │ 설명 (Description)                       │
├──────────────────────┼─────────────┼─────────────────────────────────────────┤
│ id                   │ BIGINT (PK) │ 자동 증가 고유 ID                       │
│ frame_id             │ INT         │ 프레임 번호 (FK -> sf_frame_summary)    │
│ person_id            │ INT         │ 프레임 내 보행자 인덱스 번호            │
│ bev_x_m              │ DOUBLE      │ BEV 물리 X 좌표 (미터 단위)             │
│ bev_y_m              │ DOUBLE      │ BEV 물리 Y 좌표 (미터 단위)             │
│ detection_source     │ VARCHAR(16) │ 감지 소스 ('CCTV', 'LiDAR', 'Fused')    │
└──────────────────────┴─────────────┴─────────────────────────────────────────┘

다. 테이블 3: 구역별 위험도 통계 (sf_roi_risk_log)
┌──────────────────────┬─────────────┬─────────────────────────────────────────┐
│ 컬럼명 (Column)       │ 데이터 타입 │ 설명 (Description)                      │
├──────────────────────┼─────────────┼─────────────────────────────────────────┤
│ log_id               │ BIGINT (PK) │ 로그 고유 일련번호                      │
│ frame_id             │ INT         │ 프레임 번호 (FK -> sf_frame_summary)    │
│ roi_id               │ INT         │ 구역 ID                                 │
│ roi_name             │ VARCHAR(64) │ 구역명 (예: 'Cafe_Entrance_Zone')       │
│ people_in_roi        │ INT         │ 해당 구역 내 검출 인원수                │
│ occupancy_intensity  │ DOUBLE      │ 해당 구역 평균 점유 확률값 (0.0~1.0)     │
│ risk_score           │ DOUBLE      │ 계산된 최종 위험 스코어 (0.0~100.0)      │
│ risk_level           │ VARCHAR(16) │ 위험 단계 ('SAFE', 'CAUTION', 'DANGER') │
└──────────────────────┴─────────────┴─────────────────────────────────────────┘
