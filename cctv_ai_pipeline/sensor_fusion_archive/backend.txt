                    CCTV & LiDAR 센서 퓨전 프로젝트 
                   백엔드 적재 설계 및 비용 분석 보고서
================================================================================

본 문서는 CCTV-LiDAR 센서 퓨전 파이프라인에서 발생하는 실시간 데이터 및 미디어 파일을 
효율적으로 적재하기 위해 Supabase와 AWS S3를 비교 분석하고, 추천 아키텍처를 제시합니다.

--------------------------------------------------------------------------------
1. 적재 데이터 분석 (데이터 유형별 분류)
--------------------------------------------------------------------------------

가. 정형 및 시계열 데이터 (수치 / 위치 / 이벤트)
   - sf_frame_summary (프레임별 센서 퓨전 요약 통계)
   - sf_pedestrian_history (보행자별 실시간 BEV 위치 좌표)
   - sf_roi_risk_log (구역별 실시간 위험도 통계)
   - 특징: 매 프레임(초당 수십 회) 발생하며, 빠른 INSERT와 실시간 대시보드 쿼리 조회가 필요함.

나. 비정형 및 대용량 미디어 데이터 (파일)
   - CCTV 비디오 프레임 스냅샷 / 원본 비디오 클립
   - LiDAR Raw 포인트 클라우드 파일 (.bin, .pcd)
   - 센서 퓨전 결과 BEV 히트맵 이미지
   - 특징: 파일 용량이 크며, 데이터베이스에 직접 적재하기 어렵고 파일 스토리지 저장이 필수적임.

--------------------------------------------------------------------------------
2. 백엔드 플랫폼 비교 (Supabase vs AWS S3)
--------------------------------------------------------------------------------

가. Supabase (PostgreSQL 기반 BaaS)
   - 역할: 관계형 데이터베이스(RDBMS) + 파일 스토리지 + 실시간 API 서버 통합 제공.
   - 장점:
     1. PostgreSQL 제공으로 정형 데이터의 복잡한 통계 및 공간(PostGIS) 쿼리 지원.
     2. 실시간(Realtime) 구독 기능 기본 지원으로 DB 변경 사항을 대시보드 화면에 소켓 통신으로 즉시 전송 가능.
     3. 인증(Auth) 및 스토리지 API가 자동 생성되어 개발 리소스 대폭 절감.
   - 한계: 무료 DB 용량(500MB)이 제한적이므로 대규모 장기 적재 시 아카이빙 로직 필요.

나. AWS S3 (객체 저장소)
   - 역할: 대용량 이미지, 비디오, 대형 로그 백업용 단순 정적 파일 저장소.
   - 장점:
     1. 용량 한계가 없으며 기가바이트(GB)당 단가가 매우 저렴함.
     2. AWS 생태계(Athena, Lambda, AI 파이프라인 등)와의 결합성이 탁월함.
   - 한계: 관계형 데이터 쿼리나 행(Row) 단위의 실시간 CRUD 작업이 불가능함.

--------------------------------------------------------------------------------
3. 데이터 발생량 및 데이터베이스 용량 추정
--------------------------------------------------------------------------------

- 설정 조건: 10 FPS 작동, 평균 보행자 수 5명, ROI 구역 2개 기준
- 시간당 적재 행(Row) 수:
  - sf_frame_summary     : 10 FPS * 3600초 = 36,000 Row
  - sf_pedestrian_history : 10 FPS * 5명 * 3600초 = 180,000 Row
  - sf_roi_risk_log      : 10 FPS * 2구역 * 3600초 = 72,000 Row
  - 합계: 약 288,000 Row / 1시간 (하루 작동 시 약 6,912,000 Row)

- 용량 환산 시:
  - 하루 적재 데이터(텍스트/숫자)는 약 300MB ~ 500MB 내외의 DB 용량을 차지합니다.
  - 여기에 프레임 이미지나 LiDAR 데이터 파일까지 DB에 저장하게 되면 기하급수적으로 증가합니다.

--------------------------------------------------------------------------------
4. 백엔드 서비스별 가격 및 비용 분석 (2026년 기준)
--------------------------------------------------------------------------------

가. Supabase 요금제
   - Free Plan (개발/테스트용)
     * 비용: $0 / 월
     * 제공: PostgreSQL 500MB, Storage 1GB, 대역폭 2GB/월, 실시간 접속 200명
   - Pro Plan (소규모~중규모 서비스)
     * 비용: $25 / 월
     * 제공: PostgreSQL 8GB 포함 (초과 시 $0.125/GB당)
     * 제공: Storage 100GB 포함 (초과 시 $0.021/GB당)
     * 제공: 대역폭 50GB/월 포함 (초과 시 $0.09/GB당)

나. AWS S3 요금제 (Seoul 리전, Standard Storage 기준)
   - 무료 티어: 가입 후 12개월간 5GB 무료
   - 종량제 비용:
     * 저장 비용: $0.025 / GB / 월
     * 인터넷 데이터 전송(Egress): $0.126 / GB (매월 100GB 무료 제공 후 청구)
     * 요청 비용: GET 1만 건당 약 $0.004 / PUT 1천 건당 약 $0.005

--------------------------------------------------------------------------------
5. 추천 백엔드 아키텍처 (AWS S3 + Supabase 하이브리드)
--------------------------------------------------------------------------------

사용자 제안인 [대용량 영상/미디어 -> AWS S3] 및 [CCTV 분석 결과 및 관제 -> Supabase] 모델은 
비용과 실시간 성능을 모두 잡을 수 있는 가장 이상적인 설계입니다.

가. 역할 분담 구조

┌──────────────────────────────────────┐     ┌──────────────────────────────────────┐
│                AWS S3                │     │         Supabase (Postgres)          │
├──────────────────────────────────────┤     ├──────────────────────────────────────┤
│ - CCTV 원본 비디오 파일                │     │ - 프레임별 분석 통계                    │
│ - LiDAR Raw (.pcd) 파일               │     │ - 실시간 보행자 좌표                   │
│ - BEV 히트맵 이미지                    │     │ - ROI 위험도 로그                      │
│ - 백업용 시계열 CSV                    │     │ - S3 파일의 URL 링크                   │
└──────────────────────────────────────┘     └──────────────────────────────────────┘

나. 시나리오 데이터 흐름 (Data Flow Example)
   1) [AI 파이프라인] CCTV/LiDAR 데이터 기반 실시간 객체 탐지 및 센서 퓨전 실행.
   2) [미디어 저장] 기록이 필요한 원본 비디오/BEV 이미지를 AWS S3에 비동기로 업로드 -> 업로드 완료 후 S3 URL 획득.
   3) [분석결과 적재] 융합 데이터 결과 및 S3 URL을 하나의 Payload로 구성하여 Supabase PostgreSQL에 INSERT.
   4) [실시간 관제] Supabase Realtime 리스너를 구독 중인 웹 대시보드가 데이터 삽입을 감지하여 실시간 위험도 경고 및 보행자 좌표를 화면에 갱신.

다. 하이브리드 아키텍처의 장점
   - 비용 효율성: 기하급수적으로 늘어나는 미디어 파일은 기가바이트당 약 30원($0.025)인 S3에 위임하여 Supabase 데이터베이스 용량 초과 비용($0.125/GB)을 크게 방어합니다.
   - 빠른 프론트엔드 연동: 백엔드 API를 직접 구축할 필요 없이 Supabase Client SDK로 DB 입력 이벤트 및 S3 미디어 URL을 즉각 화면에 표시할 수 있습니다.
