# CCTV 보행자 분석 파이프라인 GPU 가속 및 데이터 무결성 최적화 설계서

본 문서는 실시간 CCTV 관제 시스템의 성능 최적화를 위해 적용된 AI 추론 및 좌표 추출 파이프라인의 가속 설계 내용을 기술합니다.

---

## 1. 개요 및 변경 목적
* **이전 방식의 한계**: 
  AI 모델(CSRNet)의 원래 출력 해상도인 `160x90` 히트맵을 CPU 상에서 강제로 `1280x720`으로 확장(cv2.resize)한 뒤, CPU 단일 스레드로 극대값 필터링(Maximum Filter)을 전수조사하여 1분 영상 처리 시 약 15~20분 소요.
* **변경 목적**:
  1. 가상 데이터 뻥튀기(Resize 보간 왜곡)를 배제하여 **100% 무결한 AI 원본 데이터 좌표 확보**.
  2. GPU 병렬 연산 및 연산 면적 축소(64배 감소)를 통해 대폭 가속.
  3. 3개 구역 비디오의 **병렬 동시 처리**를 통해 직렬 합산 시간을 병렬 최대 시간으로 단축.

---

## 2. 가속화 아키텍처 비교 (비유 분석)

### 🔍 기존 방식 : 작은 디지털 도장을 초대형 전지에 늘려놓고 돋보기로 찾기
* **과정**: AI 추론 완료(`160x90` 히트맵) ➡️ CPU 리사이즈(`1280x720` 확장) ➡️ 데이터 왜곡 발생(흐릿하게 뭉개짐) ➡️ CPU 싱글스레드 필터링(92만 화소 전수조사) ➡️ 3구역 직렬 합산 실행.
* **문제점**: 억지로 해상도를 키우는 과정에서 가상 픽셀이 보간되어 **실제 보행자의 위치가 픽셀 단위로 미세하게 빗나가는 왜곡**이 생기며, 연산 대상 화소수가 92만 개로 급증하여 심각한 병목 유발.

### ⚡ 개선 방식 (1순위 가속 적용) : 작은 디지털 도장 원본 그대로 초정밀 현미경으로 1초 만에 찾기
* **과정**: AI 추론 완료(`160x90` 히트맵) ➡️ GPU MaxPool2d(1.4만 화소 0.1ms 내 필터링) ➡️ 극소 마스크만 CPU 전송(메모리 지연 제거) ➡️ `160x90` 스케일 상에서 초경량 라벨링(0.5ms) ➡️ 정직한 축척 복원(가로8배/세로8배 곱연산).
* **핵심 이점**: 
  1. 가짜 픽셀을 생성해내는 `Resize`를 완전히 생략하여 **데이터의 정밀도와 무결성 극대화**.
  2. 뒤져야 하는 연산 공간의 크기가 **64분의 1로 급감** (92만 ➡️ 1.4만).
  3. GPU의 수천 개 CUDA 코어가 병렬 비교 연산을 수행하여 **단 0.0001초 만에** Peak 픽셀 추출 완료.

## 3. 세부 기술 구현

### 1) GPU 기반 극대값(Local Maxima) 고속 검출
* PyTorch의 2D 최대 풀링(`F.max_pool2d`)을 사용하여 5x5 영역 내의 최대값을 GPU 내부에서 초고속 연산합니다.
* `F.max_pool2d(-density)` 음수 트릭을 활용해 최소값 필터링(Min Pool) 역시 GPU에서 Zero-Copy로 연쇄 가동합니다.

### 2) 저해상도 라벨링 및 정직한 축척 복원 (Scale Back)
* AI 고유 출력 해상도인 `160x90` 텐서에서 추출한 Peak 픽셀 위치 `(px_raw, py_raw)`에 대해서만 720p 입력 해상도 비율(`scale_x = 1280.0 / w_out`, `scale_y = 720.0 / h_out`)을 단순 수학적 곱연산으로 복원.
* 중간 보간 왜곡이 원천 차단됩니다.

### 3) FPS 샘플링 인터벌 최적화 (2026-08-05 추가)
* **버그 수정**: `04_video_to_bev_CSR.py` 내에 `target_fps = 15.0`으로 하드코딩되어 있어 외부에서 `--fps` 인자를 전달해도 무시되던 버그를 수정.
* **수정 내용**: 환경변수 `TARGET_FPS`를 우선으로 읽고 기본값 `10.0`을 적용하도록 변경.
  ```python
  # 수정 전 (하드코딩 버그)
  target_fps = 15.0
  # 수정 후
  target_fps = float(os.environ.get("TARGET_FPS", "10.0"))
  ```
* **10 FPS 선택 근거**: 5 FPS는 보행자 추적(Tracking) ID가 끊기는 임계점 이하이며, 15 FPS 대비 33% 연산량 감소. 10 FPS는 `100ms` 프레임 간격으로 일반 보행 속도에서 동일인물 추적이 안정적으로 유지되는 현업 표준 최소 임계값.

### 4) cap.grab() 기반 비디오 디코딩 최적화 (2026-08-05 추가)
* **기존 문제**: 스킵 대상 프레임도 `cap.read()`를 호출해 압축 해제(디코딩)를 수행하여 CPU 자원 낭비.
* **수정 내용**: 스킵 대상 프레임은 `cap.grab()`(포인터만 이동)으로 처리하여 실제 분석 대상 프레임만 `cap.read()`(디코딩)를 실행.
  ```python
  if (frame_count - 1) % skip_interval != 0:
      if not cap.grab():   # 포인터만 이동 (디코딩 없음)
          break
      pbar.update(1)
      continue
  ret, frame = cap.read()  # 분석 대상 프레임만 실제 디코딩
  ```

### 5) 3개 구역 병렬 처리 (ThreadPoolExecutor) (2026-08-05 추가)
* **기존 구조 (직렬)**: `load_zone_pedestrian_data.py`에서 Zone 1 → Zone 2 → Zone 3을 순차적으로 실행하여 처리 시간이 3개 구역 소요 시간의 합산.
* **개선 구조 (병렬)**:
  - **Phase 1 (병렬)**: `concurrent.futures.ThreadPoolExecutor(max_workers=2)`를 사용해 3개 구역의 무거운 CSRNet AI 추론(04단계)을 동시 실행. GPU OOM 방지를 위해 최대 2개 동시 실행으로 제한.
  - **Phase 2 (순차)**: 경량 집계(09단계)는 동일한 출력 파일(`pedaggr01h_full_dataset.json`)에 쓰기 충돌이 발생하므로 순차 실행 유지.
* **병렬화 효과**: 직렬 합산 311초 → 병렬 최대값 기준 약 200초 내외 (2개 동시 실행 시 GPU OOM 없이 안정)

### 6) 히트맵 시각화 품질 보완 (웹 대시보드 위임)
* **서버 부하 분산**: 서버는 오직 좌표와 보행자 수만 DB에 빠르게 적재하고 종료합니다.
* **대시보드 동적 렌더링**: 대시보드(클라이언트 브라우저 Canvas)가 원본 영상 위에 보행자 2D 픽셀 좌표를 띄울 때, 웹 렌더링 엔진의 smooth 보간 필터링(Bilinear Filtering)을 적용하여 **모자이크 깨짐 현상이 전혀 없는 매끄러운 가우시안 안개형 히트맵을 웹 화면에 동적으로 생성**합니다.

## 5. 실시간 vs 업로드 파이프라인 설계 원칙

| 구분 | 실시간 (Stream) | 업로드 (File Batch) |
| :--- | :--- | :--- |
| **최우선 가치** | 초저지연 (Latency) | 높은 정확도 (Accuracy) |
| **데이터 소스** | RTSP/RTMP 라이브 스트림 | 완성된 .mp4 업로드 파일 |
| **FPS 처리** | 10~15 FPS 스킵 (속도 우선) | 원본 FPS 전수 (정밀도 우선) |
| **Peak 추출** | GPU MaxPool (본 설계 방식) | GPU MaxPool + 배치 크기 확대 |
| **데이터 전달** | Redis/Kafka 메시지 큐 → WebSocket | DB Bulk Insert (일괄 적재) |
| **구현 엔드포인트** | 별도 스트리밍 API 분리 필요 | `/api/v1/cctv/upload` |

> **핵심**: 두 파이프라인은 목표가 상반되므로 엔드포인트와 처리 로직을 반드시 물리적으로 분리 설계해야 합니다.

## 6. 향후 개선 방향
* GPU VRAM 여유 확인 후 `max_workers=3` 복원 또는 GPU 메모리 효율화 (모델 공유 인스턴스 사용).
* 비디오 디코딩을 별도 백그라운드 스레드 큐에서 선제 수행하여 AI 추론 대기 시간 제거 (생산자-소비자 패턴 적용).
* NVDEC(하드웨어 GPU 디코더) 활성화로 디코딩 병목 완전 제거.
